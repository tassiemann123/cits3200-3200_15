## Getting Started (for anyone cloning this repo fresh, including the Auditor)

### Prerequisites
- Node.js 22 or later (24 LTS recommended)
- pnpm (for the mobile app): `corepack enable`, or `npm install -g pnpm`
- JDK 21 (comes bundled with Android Studio, no separate install needed)
- Android Studio, if you want to run the app on an emulator or device
- Docker and Python 3.12, only if you want to run the backend

Check what's installed:
```
node -v
pnpm -v
java -version
```

### Get the 3D model
The skeleton model is not stored in this repository (see Attribution below). Download it from Sketchfab and place it at `mobile/public/models/skeleton_pre-cut.glb`. The desktop build copies it from there. If the file is missing the build skips the model step with a warning, but no skeleton model will be shown.

### Run the mobile app as a website (fastest way to preview, no Android Studio needed)
```
cd mobile
pnpm install
pnpm run dev
```
Then open the printed `localhost` link in a browser.

### Run the mobile app as an actual Android app
```
cd mobile
pnpm install
pnpm run android:sync
pnpm run android:open
```
`android:sync` builds the web app and copies it into the Android project. `android:open` opens the project in Android Studio. From there, press the Run button (green triangle) with an emulator or connected device selected.

Note: there is no single `requirements.txt` for the whole project. The mobile app lists its dependencies in `mobile/package.json` (locked by `mobile/pnpm-lock.yaml`), the desktop app in `desktop/package.json`, and the backend in `backend/requirements.txt`. `pnpm install` (mobile), `npm install` (desktop) and `pip install -r requirements.txt` (backend) install them.

## Mobile App

Android app for on-site fieldwork: CFA coordinate entry for multiple skeletons, a 3D reference skeleton posed from the entered points, a compass and GPS, CSV import and export, and sync to the backend. See [`mobile/README.md`](mobile/README.md).

### Stack
- Node.js and pnpm
- Vite (bundler)
- React + TypeScript
- Three.js (3D skeleton viewer)
- Capacitor (wraps the web app into an Android app)
- Vitest (tests)

### Current project structure
```
mobile/
├── index.html            entry page
├── src/
│   ├── main.tsx          entry point, mounts the app
│   ├── App.tsx           the main component, top of the UI tree
│   ├── components/       UI pieces (3D viewport, coordinate panel, compass, ...)
│   ├── data/             landmark schema and skeleton piece definitions
│   └── lib/              CSV parsing and export, pose maths, backend API, storage
├── public/               static files served as-is
│   ├── samples/          example coordinate CSVs
│   └── models/           the GLB skeleton model (not in Git)
├── android/              native Android project generated by Capacitor, don't hand-edit much here
├── package.json          lists dependencies and scripts
├── pnpm-lock.yaml        locked dependency versions
├── capacitor.config.ts   Capacitor's settings (app name, ID, etc.)
└── vite.config.ts        bundler config
```

### Day-to-day commands
Run these from `mobile/`:
```
pnpm run dev            run as a normal website locally, fastest way to preview changes
pnpm run test           run the unit tests
pnpm run typecheck      check the TypeScript
pnpm run android:sync   build and push the web app into the Android project
pnpm run android:open   open in Android Studio to run on emulator or device
```

## Backend

FastAPI and PostgreSQL, shared by the mobile and desktop apps. See [`backend/README.md`](backend/README.md) to start it (Docker for the database, then `uvicorn`).

Networking notes:
- A browser connects to `http://127.0.0.1:8000`.
- The Android emulator reaches the host computer at `http://10.0.2.2:8000`.
- For a physical phone, copy `mobile/.env.example` to `mobile/.env.local` and set `VITE_API_URL` to the host computer's LAN address, for example `http://192.168.1.100:8000`.

The backend has no login or access control yet, so do not expose it to untrusted networks with real field records.

## Desktop App

Windows desktop app built as an installable web app that works offline, with an Electron wrapper. It uses React, TypeScript, Vite and Three.js, and syncs to the same backend as mobile (with separate storage). Unlike mobile, it uses npm. See [`desktop/README.md`](desktop/README.md).

```
cd desktop
npm install
npm run dev
```
